# 分享：把攻略发到微信 / QQ

> 实测见 `research/04-微信QQ分享.md`（macOS 26 / WeChat 4.1.15 / QQ 7.0.3）。

## 结论

**默认走 A：生成长图 + 文案 → 写入剪贴板 → 唤起微信/QQ → 用户自己粘贴发送。**
不自动点"发送"，不会发错人，也不依赖非官方协议。

## A. 标准流程（推荐）

```bash
# 1) 生成 750px 长图（Edge headless，中文正常）
python3 .dsh/skills/travel-guide/scripts/share_card.py 分享卡片.json -o 攻略长图.png

# 2) 图片放进剪贴板（可选）
python3 .dsh/skills/travel-guide/scripts/share_card.py 分享卡片.json -o 攻略长图.png --copy

# 3) 唤起微信（QQ 用 --open qq）
python3 .dsh/skills/travel-guide/scripts/share_card.py 分享卡片.json -o 攻略长图.png --open wechat
```

用户在微信里选联系人 → `Cmd+V` → 发送。剪贴板一次只能装一种内容，所以：
**图片和文案分开粘贴**，或者把文案直接排进长图底部（推荐）。

技术要点：
- Edge headless 必须加 `--no-sandbox`，否则在 DSH 沙箱里 GPU 进程直接 fatal。
- `--window-size` 的高度就是截图高度；脚本先截 6000px 再用 Pillow 裁掉底部空白。
- 750px 宽接近手机阅读宽度；长图不要超过 20000px，部分客户端会压缩。
- 没有 Edge 时用 Pillow 直接画（`/System/Library/Fonts/Hiragino Sans GB.ttc` 中文可用）。

## B. 如果在 DSH 里，优先看有没有 `send_wechat` 工具

本会话可用一个 `send_wechat` 工具（iLink 通道）：能直接把文字或工作区内的文件推到微信。

- 适合"发给自己 / 文件传输助手"。
- **限制**：bot 只能在用户最后一条消息后 24 小时内主动推送，超时要用户先发一条。
- 文件必须在会话工作区内，且有大小上限。

做分享时先看当前会话有没有这个工具；有就直接用，没有就走 A。

## C. 不要做的

| 做法 | 为什么不行 |
|---|---|
| AppleScript 控制微信发消息 | WeChat 没有 scripting dictionary，只能读 version；窗口查询会挂起 |
| AX 自动搜联系人 → 粘贴 → 发送 | 微信 Qt 自绘，`AXWindows=0`；QQ 只有 25 个骨架元素、没有输入框；cua 报 `ax_window_unresolved` |
| 系统分享面板 | 微信/QQ 的 share extension 装了，但 `NSSharingServicePicker` 里不出现 |
| 个人号协议机器人 | 需要额外协议端/账号，有风控与掉线风险，只适合长期自动通知 |

## D. 真要"自动推送"时

- 优先 **QQ 官方机器人** 或 **企业微信**，而不是个人号非官方协议。
- DSH 侧对应插件：`dsh-onebot-qq` / `dsh-channel-qq`（OneBot v11，需 NapCat 等协议端）、
  `@lanbaolu/dsh-wechat-bridge`（iLink 扫码桥接）、`dsh-wechat-mp`（只做公众号草稿）。
- `dsh-wechat-transfer` 虽然最像"文件传输助手"，但只支持 Windows。

## 分享文案模板

```
【成都 3 日】11/15-11/17，人均 1800
Day1 老城+火锅 / Day2 熊猫+三星堆 / Day3 小吃返程
3 条避坑：博物馆周一闭馆、熊猫 11 点后睡觉、网红店别在景区里吃
路线图见下图，详细版：<链接或文件名>
```

- 群发时给"一句话结论 + 一个钩子"，细节放图里。
- 涉及他人笔记的内容，写"参考了 XX（链接）"，不要把别人的攻略整段搬走。
