## 0. 一句话结论

**做旅游攻略的路线图，90% 的场景不需要 Key。**
用「高德 URI API 分享链接 + 本地自绘 SVG 路线图」就能覆盖"看路线、能导航、能发微信"三件事；
只有需要**精确驾车/公交耗时、真实里程、POI 搜索、天气**时才去申请 Key（个人实名认证后免费额度够用）。

| 需求 | 方案 | 要 Key 吗 | 成本 |
|---|---|---|---|
| 行程配一张路线示意图 | 本地 Python 画 SVG（`amap_route_demo.py`） | ❌ | 0 |
| 点开链接看地图 / 导航 | `uri.amap.com/marker`、`/navigation` | ❌ | 0 |
| PC 上打开网页版路线 | `ditu.amap.com/dir?...` | ❌ | 0 |
| 真实驾车/公交耗时、实际里程 | Web 服务 API `v3/direction/*` | ✅ | 个人认证免费额度内 0 元 |
| 搜 POI、地理编码、天气 | Web 服务 API `v3/place/text` 等 | ✅ | 同上（搜索仅 5000 次/月） |

## 2. 高德官方 MCP Server

官方文档：<https://developer.amap.com/api/mcp-server/summary>

### 2.1 它是什么

2025-03 首发、2025-05 升级，把高德的 LBS 能力包成 MCP 工具，供 Cursor / Claude / Cline 等**任意支持 MCP 协议的客户端**调用。
它**不是**一套新的免费接口，本质仍是「用你的 Key 调高德 Web 服务能力，再包一层 MCP 协议」——Key 是前提。

### 2.2 两种接入方式（官方原文）

**A. Streamable HTTP（官方推荐）**

```json
{
  "mcpServers": {
    "amap-maps-streamableHTTP": {
      "url": "https://mcp.amap.com/mcp?key=您在高德官网上申请的key"
    }
  }
}
```

**B. Node.js I/O（需 Node ≥ v22.14.0 与本机 `npx`）**

```json
{
  "mcpServers": {
    "amap-maps": {
      "command": "npx",
      "args": ["-y", "@amap/amap-maps-mcp-server"],
      "env": { "AMAP_MAPS_API_KEY": "您在高德官网上申请的key" }
    }
  }
}
```

> 本机**没有 npm/npx**，方式 B 不可用；方式 A 只需 HTTP，任何环境都能接。
> 但注意：**本项目的攻略生成根本不需要 MCP** —— MCP 是给"聊天客户端里让大模型自己调工具"用的，
> 我们要的是"生成一次静态路线图 + 一串链接"，直接用 HTTP / URI 更轻、更可控。

### 2.3 能力清单（官方"能力介绍"原文归纳）

| 能力 | 输入 | 输出 |
|---|---|---|
| 生成专属地图 | 行程名称、行程详情（每日行程、途径点位） | **专属地图唤端链接**（把攻略导入高德 App 生成私有地图） |
| 导航到目的地 | 目的地经纬度 | 高德导航唤端链接 |
| 打车 | origin、destination | 高德打车唤端链接 |
| 地理编码 | address、city(可选) | 经纬度 |
| 逆地理编码 | 经纬度 | 省市区等地址组成 |
| IP 定位 | IP | 省、市、adcode |
| 天气查询 | 城市名或 adcode | 预报天气 |
| 骑行路径规划 | origin、destination | 距离、时间、步骤（≤500 km） |
| 步行路径规划 | origin、destination | 路径数据（≤100 km） |
| 驾车路径规划 | origin、destination | 路径数据 |
| 公交路径规划 | origin、destination、city、cityd | 路径数据（跨城必须传城市） |

其中**「生成专属地图」是 MCP 独有的高价值能力**：能把整份行程（点位 + 描述）一键导入高德 App 变成私有地图。
如果将来要在 DSH 里做"一键导入高德"，优先评估它；它需要 Key。

## 3. Web 服务 API 与 Key

### 3.1 端点（实测无 Key 全部返回 `INVALID_USER_KEY`，说明端点真实存在）

```
https://restapi.amap.com/v3/direction/driving?origin=&destination=
  -> {"status":"0","info":"INVALID_USER_KEY","infocode":"10001"}
https://restapi.amap.com/v3/geocode/geo?address=
https://restapi.amap.com/v3/place/text?keywords=&city=
https://restapi.amap.com/v3/weather/weatherInfo?city=
https://restapi.amap.com/v3/distance?origins=&destination=      # 距离矩阵/距离测量
```

（`v3/staticmap` 静态地图同样在配额范围内，属于"基础 LBS 服务"。）

### 3.2 Key 申请流程（官方"创建应用和 Key"四步）

1. 登录 <https://console.amap.com>（无账号先注册成为开发者）
2. 【应用管理】→ 右上角【创建新应用】→ 填表单
3. 进入应用 → 【添加 Key】→ **服务平台必须选【Web 服务】**（选错平台调不通 REST API）
4. 创建成功后可拿到 **Key** 与 **安全密钥**

### 3.3 实名认证：**必须**，个人认证即可

- 2021-08-05 公告：未认证个人开发者**无法新增 Key**，已删除的应用/Key 不可恢复
- 2022-09-20 公告：未认证开发者的**各接口调用权限逐步被关闭**

> 结论：**能免费申请，但必须先做实名认证**（个人身份即可，无需企业）。
> 个人认证的适用范围是"**非商业目的**"；商业用途须走企业认证或购买技术服务许可。

### 3.4 免费额度（官方定价页，2025-05-20 起执行）

个人认证开发者享有**自认证之日起 1 年**的免费月配额：

| 服务 | 包含接口 | 个人认证 | 企业认证 |
|---|---|---|---|
| 基础 LBS 服务 | **路径规划**、**距离测量**、地理编码、逆地理编码、坐标转换、行政区划、IP 定位、静态地图 | **150,000 次/月** | 3,000,000 |
| 基础搜索服务 | 关键字/周边/多边形/ID 查询、输入提示 | **5,000 次/月** | 50,000 |
| 天气查询 | 天气预报 | **5,000 次/月** | 5,000 |
| 基础地图定位 | JS 图面初始化、在线定位 | 1,500,000 | 30,000,000 |
| 智能硬件定位 | — | 0（不开放） | 5,000 |

- 超出后按量付费：基础 LBS / 搜索 **30 元/万次**，地图定位 3 元/万次；量大可谈折扣
- 并发（QPS）另有上限，加钱买「QPS 包」提升：400~1500 元/月/10 QPS
- **两个坑**：① 免费额度只有 **1 年**（自认证日起算）；② **搜索类只有 5000 次/月**，POI 搜索最容易超

### 3.5 对本项目的用量估算

一份攻略大致消耗：地理编码 10~30 次 + 驾车/公交规划 20~50 次 + 天气 1 次 ≈ **百次级**。
个人认证的 15 万/月额度绰绰有余；真正需要担心的是搜索类 5000/月（做 POI 批量抓取会爆）。

## 4. 无 Key 兜底方案（全部实测通过）

### 4.1 单点 / 多点标注 —— `uri.amap.com/marker`

| 参数 | 值 | 说明 | 必选 |
|---|---|---|---|
| `position` | `lon,lat` | 单点标注坐标 | 单点必选 |
| `name` | 任意 | 自定义显示名称 | 否 |
| `markers` | `lon,lat,名称\|lon,lat,名称` | 多点标注，**N ≤ 10**，用 `|` 分隔 | 多点必选 |
| `coordinate` | `gaode` / `wgs84` | 坐标系声明，默认 gaode（GCJ-02） | 否 |
| `poiid` | POI ID | 用 POI ID 代替坐标 | 否 |
| `callnative` | 0 / 1 | 是否尝试唤起高德 App（仅移动端） | 否 |
| `src` | 任意 | 使用方来源标识 | 否 |

```
https://uri.amap.com/marker?position=116.397128,39.916527&name=天安门
https://uri.amap.com/marker?markers=116.397128,39.916527,天安门|116.481488,39.990464,望京&src=dsh
```

### 4.2 路径规划 —— `uri.amap.com/navigation`

| 参数 | 值 | 说明 |
|---|---|---|
| `from` | `lon,lat[,名称]` | 起点；**留空则用用户当前位置（仅移动端）** |
| `to` | `lon,lat[,名称]` | 终点 |
| `via` | `lon,lat[,名称]` | 途经点，**最多 1 个，且仅驾车模式有效** |
| `mode` | `car` / `bus` / `walk` / `ride` | 缺省 car；**骑行仅移动端有效** |
| `policy` | 驾车 0 推荐 / 1 避堵 / 2 避收费 / 3 不走高速；公交 0 最佳 / 1 换乘少 / 2 步行少 / 3 不坐地铁 | 缺省 0 |
| `callnative` | 0 / 1 | 唤起 App（仅移动端） |
| `src` | 任意 | 来源标识 |

```
https://uri.amap.com/navigation?from=116.397128,39.916527,天安门&to=116.481488,39.990464,望京&mode=car&policy=0&src=dsh
```

### 4.3 实测：URI 会 302 到哪里（关键证据）

用不同 UA 请求，得到完全不同的落地页（`curl -L` 记录最终 URL，2026-11-09）：

| UA | 请求 | 最终落地 | 状态 |
|---|---|---|---|
| 桌面 Chrome | `/marker` | `https://ditu.amap.com/regeo?lng=…&lat=…&name=…&innersrc=uriapi` | 200 |
| 桌面 Chrome | `/navigation` | `https://ditu.amap.com/dir?type=car&policy=1&from[lnglat]=…&to[lnglat]=…` | 200 |
| 微信 iPhone | `/marker` | `https://m.amap.com/share/index/lnglat=…&name=…` | 200 |
| 微信 iPhone | `/navigation&mode=car` | `https://m.amap.com/navigation/carmap/saddr=…&daddr=…` | 200 |
| 微信 iPhone | `mode=bus` | `https://m.amap.com/navigation/buslist/…` | 200 |
| 微信 iPhone | `mode=walk` | `https://m.amap.com/navigation/walkmap/…` | 200 |
| 微信 iPhone | `mode=ride` | `https://m.amap.com/navigation/ridemap/…` | 200 |
| 微信 iPhone | 多点 `markers` | `https://m.amap.com/search/mapview/markers=…` | 200 |

**↳ 微信里能直接打开吗？**
**能打开 H5 页面，但唤不起高德 App。** 官方对 `callnative` 明确写着：
"部分第三方平台内置浏览器无法成功调起，例如**微信、QQ**"。
所以链接发微信可用（点开就是一页地图/路线），但要真正导航，需要用户点右上角「在浏览器中打开」。
若在微信里发 `callnative=1` 没有副作用（不会报错），只是不生效——**发微信一律用 `callnative=0` 更干净**。

### 4.4 网页版路线 URL 能不能自己拼：能

```
https://ditu.amap.com/dir?type=car
  &from%5Blnglat%5D=116.397128,39.916527&from%5Bname%5D=天安门
  &to%5Blnglat%5D=116.481488,39.990464&to%5Bname%5D=望京
```

实测直拼返回 **200 / 77 KB**。注意两点：
1. `[]` 必须做 URL 编码（`%5B` `%5D`），否则部分客户端会截断；
2. 页面是 SPA 壳（`<title>` 为空，靠 JS 渲染），**服务端拿不到路线文本**——想让程序读出"多少公里、多少分钟"，必须用 Key 调 API。

`type` 可取 `car` / `bus` / `walk` / `ride`（car 已实测；其余为同一路由的枚举值，未逐一出证）。

## 5. 决策：什么时候用 Key

```
需要"多少公里 / 多久到"的准确数字？ ── 是 ──> 用 Key 调 v3/direction/*（个人认证免费额度足够）
              │
              否
              ↓
需要 POI 搜索 / 地理编码 / 天气？ ── 是 ──> 用 Key（注意搜索仅 5000 次/月）
              │
              否
              ↓
只要能看、能分享、能导航 ──> 不用 Key：SVG 示意图 + URI 链接（本方案默认路径）
```

| 场景 | 结论 | 理由 |
|---|---|---|
| 攻略里配一张路线示意图 | **不用 Key** | 自绘 SVG 更可控（可换字体、配色、中文标注），不受配额限制 |
| "点这里导航到下一站" | **不用 Key** | URI 完全够用，官方也鼓励 |
| 给同行人发一份行程 | **不用 Key** | 微信可直接打开 H5；导出 HTML 更稳 |
| 写"驾车 23 分钟 / 8.6 km" | **用 Key** | 只有 API 返回耗时与真实里程 |
| 按"附近 500m 有早餐店"筛酒店 | **用 Key** | 周边搜索是 API 能力 |
| 查行程当天的天气 | **用 Key** | 天气 API |
| 把整份行程导入高德 App | Key + MCP | MCP 的"生成专属地图"能力 |
| 批量抓 1000 个 POI | 用 Key 且算成本 | 搜索 5000/月，超了 30 元/万次 |

**默认策略：先无 Key 跑通，需要精确数据时再加 Key。**
脚本已把 Key 做成**可选增强**（`--check-key`），不配 Key 不影响主流程。

## 7. 坐标系坑（最容易翻车的地方）

### 7.1 三套坐标

| 坐标系 | 谁在用 | 与 WGS-84 的关系 |
|---|---|---|
| **WGS-84** | GPS 原始坐标、OSM、Google Earth、大部分国外数据、手机定位原始输出 | 基准 |
| **GCJ-02**（火星坐标） | **高德**、腾讯、微信内置地图、国内大部分地图 | 国测局加密偏移，**非线性、不可逆的近似** |
| **BD-09** | 百度地图 | 在 GCJ-02 上再偏移一次 |

**偏移有多大？** 实测（北京天安门附近）：

```
WGS-84 (116.3912, 39.9073) -> GCJ-02 (116.397441, 39.908701)
偏移 555 米   ← 直接拿 GPS 坐标标到高德上，会差出半条街
反向回转残差 0.00 m（迭代法）
GCJ-02 -> BD-09 -> GCJ-02 闭环残差 0.00 m
境外坐标不偏移（2.3522, 48.8566 原样返回）
```

### 7.2 什么时候要转换

| 坐标来源 | 坐标系 | 处理 |
|---|---|---|
| 高德地图点选 / 高德 URI / 高德 API | GCJ-02 | 直接用 |
| 高德「坐标拾取器」<https://lbs.amap.com/tools/picker> | GCJ-02 | 直接用 |
| 微信 `getLocation`（`type: 'gcj02'`） | GCJ-02 | 直接用 |
| 手机 GPS / 轨迹 GPX / EXIF | WGS-84 | **必须转** `wgs84_to_gcj02` |
| OSM / 维基百科 / Google Maps | WGS-84 | **必须转** |
| 百度地图 / 百度 API | BD-09 | **必须转** `bd09_to_gcj02` |
| 小红书/马蜂窝等截图里手抄的坐标 | 多半 GCJ-02 | 抽样验证一次再批量用 |

> 一个实用判据：把坐标丢进 <https://uri.amap.com/marker?position=lon,lat> 看落点。
> 落在路对面/河里 = 大概率是 WGS-84 没转。

### 7.3 转换公式（GCJ-02 加密算法）

```python
import math
A  = 6378245.0                # 克拉索夫斯基椭球长半轴
EE = 0.00669342162296594323   # 第一偏心率平方

def _tlat(x, y):   # x = lon-105, y = lat-35
    r = -100 + 2*x + 3*y + 0.2*y*y + 0.1*x*y + 0.2*math.sqrt(abs(x))
    r += (20*math.sin(6*x*math.pi) + 20*math.sin(2*x*math.pi)) * 2/3
    r += (20*math.sin(y*math.pi) + 40*math.sin(y/3*math.pi)) * 2/3
    r += (160*math.sin(y/12*math.pi) + 320*math.sin(y*math.pi/30)) * 2/3
    return r

def _tlon(x, y):
    r = 300 + x + 2*y + 0.1*x*x + 0.1*x*y + 0.1*math.sqrt(abs(x))
    r += (20*math.sin(6*x*math.pi) + 20*math.sin(2*x*math.pi)) * 2/3
    r += (20*math.sin(x*math.pi) + 40*math.sin(x/3*math.pi)) * 2/3
    r += (150*math.sin(x/12*math.pi) + 300*math.sin(x/30*math.pi)) * 2/3
    return r

def wgs84_to_gcj02(lon, lat):
    dlat = _tlat(lon-105.0, lat-35.0)
    dlon = _tlon(lon-105.0, lat-35.0)
    rad  = lat/180.0*math.pi
    m    = 1 - EE*math.sin(rad)**2
    s    = math.sqrt(m)
    dlat = (dlat*180.0) / ((A*(1-EE)) / (m*s) * math.pi)
    dlon = (dlon*180.0) / (A/s * math.cos(rad) * math.pi)
    return lon+dlon, lat+dlat
```

反向（GCJ-02 → WGS-84）没有解析解，用**迭代逼近**，3 次即到 0.1 m：

```python
def gcj02_to_wgs84(lon, lat):
    wlon, wlat = lon, lat
    for _ in range(3):
        glon, glat = wgs84_to_gcj02(wlon, wlat)
        wlon += lon - glon
        wlat += lat - glat
    return wlon, wlat
```

完整实现（含 BD-09 互转、境外判断）在 `amap_route_demo.py` 中，可直接 `import`：

```python

```

### 7.4 别忘了

- **URI 的 `coordinate=wgs84` 参数**：`uri.amap.com/marker` 支持直接传 WGS-84 让高德自己转，但 `/navigation` **没有**这个参数——导航链接必须传 GCJ-02。
- 距离开销：用 GCJ-02 坐标算 haversine，误差 < 0.5%，画示意图完全够用；算"实际驾车里程"才需要 API。
- 边界：算法只在中国境内有效（`out_of_china` 判断），境外原样返回。
