# 04 · 把攻略分享到微信 / QQ（macOS 实测）

- 调研日期：2026-11-09
- 环境：macOS 26.6（25G72，arm64）；WeChat 4.1.15（com.tencent.xinWeChat）；QQ 7.0.3（com.tencent.qq）；Microsoft Edge 157；无 Chrome；无 npm/dsh 命令
- 探测脚本与产物：`/tmp/dsh-share-probe/`（临时目录，不在项目内）
- 全程未向任何真实联系人发送消息；只做读取、枚举、剪贴板与截图探测

## 0. 结论（先看这段）

**推荐默认走 A：生成长图 + 文案 → 分别写入剪贴板 → 唤起微信/QQ → 用户自己选聊天、粘贴、点发送。**

- A 的每个组成部分都在本机实测可用（长图、中文、剪贴板图片、唤起 App），只差“用户点两下”。
- B 可作为 A 的一键化包装（复制 + 唤起 + 可选打开搜索），但不替用户按发送。
- C（AX 全自动搜联系人 → 粘贴 → 发送）在本机当前不可行，且风险最高，不建议投入。
- D（机器人通道）不是“分享给好友”的捷径：需要额外协议端/机器人账号，非官方协议有账号风险；只在需要长期自动通知时才值得。

**关键阻塞：微信和 QQ 现在都停在登录页，均未登录。**
- 微信：窗口显示「需在手机上完成登录」；AX 还读到提示「当前账号于19:22在LAPTOP-ICBLG5IU设备上登录。此客户端已退出登录。」（说明该账号在别处登录，本机被踢下线）
- QQ：登录页，已记住账号，需点「登录」并可能手机确认。
- 因此“登录后的发送”无法在本轮端到端实测；下面所有“发送”结论都以此为前提，未验证项已标注。

## 1. 程序化入口逐项核实

### 1.1 系统分享面板（NSSharingService）——扩展存在，但当前面板不列出微信/QQ

两个 App 都带 share extension，且声明支持图片/文件：

```text
/Applications/WeChat.app/Contents/PlugIns/WeChatMacShare.appex
  CFBundleDisplayName = 发送到微信
  NSExtensionPointIdentifier = com.apple.share-services
  Activation: 文件/图片/视频各最多 9 个；网页/URL 各 1 个；TRUEPREDICATE

/Applications/QQ.app/Contents/PlugIns/share.appex
  CFBundleDisplayName = 发送到QQ
  NSExtensionPointIdentifier = com.apple.share-services
  Activation: 文件/图片/视频各 1 个；支持 Text；WebURL 1 个
```

但实测**系统分享面板没有微信/QQ**。用 Objective-C 在离屏窗口里真正弹出 `NSSharingServicePicker`，读取 delegate 的 proposed services：

```text
DELEGATE proposed=8
  service: 隔空投送 / 邮件 / 信息 / 备忘录 / 添加到“照片” / 无边记 / 手记 / 提醒事项
（换一个 edge 再弹一次，仍是 8 个系统服务）
```

旧 API `+[NSSharingService sharingServicesForItems:]` 结果一致：文件 URL 8 个、纯文本 6 个，均无微信/QQ。

`pluginkit` 想确认扩展是否被系统启用，被沙箱拒绝：

```text
$ pluginkit -m -i com.tencent.qq.share
match: unauthorized discovery flag (PKDiscoverAll)
```

**结论：** appex 能力是有的，但当前这台机器的系统分享面板调不出「发送到微信/QQ」。原因未确认：可能是「系统设置 → 通用 → 登录项与扩展 → 扩展 → 共享」里未勾选，或扩展未注册。本轮不允许改系统设置，未做启用尝试。**不要把系统分享面板当成默认可用的路径。**

### 1.2 AppleScript / JXA——只能读版本，不能控制聊天

- 两个 App 的 Info.plist 都没有 `NSAppleScriptEnabled`；bundle 内也找不到 `.sdef`；`sdef` 命令本身需要完整 Xcode（本机只有 CLT），无法导出字典。
- 实测：

```text
$ osascript -e 'tell application "WeChat" to get version'
4.1.15
$ osascript -e 'tell application "QQ" to get version'
7.0.3
```

`version` 是应用的标准属性，不代表有脚本字典。继续问窗口就挂起（8 秒后强制 kill，无输出）：

```text
$ osascript -e 'tell application "WeChat" to count of windows'   # 挂起
$ osascript -e 'tell application "WeChat" to get name of every window'  # 挂起
$ osascript -l JavaScript -e 'Application("WeChat").windows.length'
0
```

**结论：** AppleScript/JXA 无法完成“搜索联系人 → 发消息”。探测时 `tell application "WeChat" to get version` 把微信拉起来了（副作用），当前微信停在登录页；未发送任何消息。

### 1.3 辅助功能 AX——微信/QQ 都没有可用的聊天 UI 树

控制进程 AX 权限本身是通的：Objective-C `AXIsProcessTrusted() == 1`。但两个 App 的窗口级 AX 都不可用：

**微信（pid 2123）**
```text
AXWindows err=0 count=0
AXFocusedWindow -> AXSheet
  AXStaticText "当前账号于19:22在LAPTOP-ICBLG5IU设备上登录。此客户端已退出登录。"
  AXButton "我知道了"
菜单栏可读：文件→发起会话；编辑→搜索；窗口→聊天/通讯录/收藏/朋友圈
```
主聊天窗口不存在（因为未登录），但即使看菜单：微信 4.x 是 Qt Quick 自绘，菜单是原生壳，聊天区不是标准 AX 控件。Windows 端的 `dsh-wechat-transfer` README 也明确写「微信 4.x 使用 Qt Quick 自绘，没有 UI Automation 元素树」——与本机 macOS 现象一致。

**QQ（pid 64177，QQNT/Electron）**
```text
AXWindows err=0 count=0
AXFocusedWindow -> AXWindow title=QQ
递归扫描仅 25 个元素，无 AXTextField / AXTextArea / AXComboBox
AXManualAccessibility 可写（err=0），但回读仍为 false
AXEnhancedUserInterface 不支持（err=-25208）
```

DSH 自带的 CUA 驱动同样拿不到窗口树：

```text
get_window_state(pid=2123, window_id=7366) -> degraded_reason: ax_window_unresolved
get_window_state(pid=64177, window_id=7477) -> degraded_reason: ax_window_unresolved
```

**结论：** “AX 搜索联系人 → 粘贴 → 发送”在当前状态下不可行。QQ 是 Electron，除非用 `--force-renderer-accessibility` 之类参数重启（会改变 App 启动方式，且未验证），否则只有骨架树；微信是 Qt 自绘，聊天区基本不暴露。**C 路线不建议。**

### 1.4 微信「文件传输助手」——macOS 没有程序化入口

- 微信没有 AppleScript 字典、没有发送文件 URL scheme（`weixin://`/`wechat://` 只负责唤起，未发现发送动作）。
- 聊天区 AX 不可用，无法自动定位「文件传输助手」。
- 唯一可复用的是 Windows 端插件 `dsh-wechat-transfer`：它用截屏 + Windows OCR + 像素点击，走「📁 → 选择文件 → 粘贴路径 → 回车」，默认 `autoSend=false`（只放进输入框，人工点发送）。但它 **只能装 Windows**（依赖 PowerShell 5.1 和中文 OCR），macOS 不可用。
- **macOS 上的现实做法：登录微信 → 用户自己点「文件传输助手」/好友 → Cmd+V。** 这也是 A 路线的一部分。

### 1.5 DSH 插件各自是什么机制

| 插件 | 机制 | 额外依赖 | 能否用于“把攻略发给好友/文件传输助手” |
|---|---|---|---|
| `@lanbaolu/dsh-wechat-bridge` 0.9.1 | 基于 wechat-claude-code 的 **iLink Bot 协议**；扫码绑定一个微信账号，插件管理本地 Node 守护进程；DSH ↔ 微信双向，支持文字/图片/文件、`/send <路径>`、`wechat_notify` | 需要扫码登录一个微信账号（README 明确：iLink 扫码是 **bot 自身登录**，不是用户配对）；非官方协议，README 自述有账号风险 | 本质是“把 DSH 变成微信机器人”，不是“分享当前文件给某个好友”的通用入口；需要常驻守护进程，且发送目标受绑定关系限制 |
| `dsh-wechat-mp` 0.3.0 | Markdown → **微信公众号草稿**；`mp_render` 只排版（无需凭据），`mp_create_draft` 等走公众号 API | 公众号 AppID/AppSecret（API 层）；不做群发，发送要人去后台确认 | 不能发个人微信好友；适合把攻略发成公众号文章 |
| `dsh-onebot-qq` 0.9.19 | **OneBot 11** QQ 机器人通道；兼容 NapCat / Lagrange / LLOneBot / go-cqhttp / SnowLuma；支持私聊/群聊、图片/语音/文件 | 需要一个 OneBot 协议端 + 登录一个 QQ 号；非官方实现，账号风控/掉线常见 | 可以发图/文件，但要求协议端和 QQ 账号，属于“机器人账号”方案，不是用户主号随手分享 |
| `dsh-channel-qq` 0.1.0 | 同样 **OneBot v11**（默认 SnowLuma，NapCat 回滚）；Node 22+；90 个工具、群聊/私聊、图片/语音/文件 | 需要协议端 + 个人 QQ 号；README 自述账号风控、掉线、重新验证是常态 | 同上；适合长期群运营/远程助手，不适合一次性分享 |

补充：`dsh-wechat-transfer`（0.2.9）虽然最贴近“发文件到文件传输助手”，但**仅 Windows**，macOS 直接排除。

**结论：** D 路线不是“少点两下”的方案，而是引入一套常驻服务和另一个账号体系；除非目标是长期自动推送/远程用微信指挥 DSH，否则不建议为“分享攻略”上 D。

## 2. 攻略长图：本机最小可行方案（已实测）

### 2.1 工具盘点（`command -v` 实测）

| 工具 | 结果 |
|---|---|
| `screencapture` | ✅ `/usr/sbin/screencapture`；实测全屏 2940×1912、按窗口 `-l 7366` 截图成功 |
| Microsoft Edge（Chromium） | ✅ 已安装，可 headless 截图 |
| Chrome / Chromium | ❌ 未安装 |
| `wkhtmltoimage` / `wkhtmltopdf` | ❌ 未安装 |
| `qlmanage` | ⚠️ 存在，但 HTML 缩略图在 DSH 沙箱下失败：`sandbox initialization failed: Operation not permitted` |
| Pillow | ✅ 12.3.0；中文字体用 `/System/Library/Fonts/Hiragino Sans GB.ttc`（PingFang.ttc、Arial Unicode.ttf 本机不存在） |

### 2.2 首选：HTML/CSS → Edge headless 长图（实测 750×2200，中文正常）

关键：DSH 的 seatbelt 会挡住 Edge 自己的 sandbox，必须加 `--no-sandbox`；否则 GPU 进程直接 fatal。命令：

```bash
EDGE="/Applications/Microsoft Edge.app/Contents/MacOS/Microsoft Edge"
"$EDGE" --headless=new --no-sandbox --disable-gpu --disable-dev-shm-usage \
  --no-first-run --no-default-browser-check --hide-scrollbars \
  --user-data-dir=/tmp/dsh-edge-profile \
  --window-size=750,2200 --virtual-time-budget=3000 \
  --screenshot="$PWD/攻略长图.png" "file://$PWD/攻略长图.html"
```

实测输出：`750×2200 RGB PNG`，标题/正文/卡片/中文字体全部正常（测试图保存在 `/tmp/dsh-share-probe/edge-long.png`）。

注意：
- `--window-size` 的高度就是截图高度（headless 截视口）。模板高度固定时最稳；内容高度不定时，可先给一个足够大的高度，再用 Pillow 按背景色裁掉底部空白。
- `--force-device-scale-factor=2` 能生成 1500×4400，但本机实测进程随后 segfault（exit 139，文件仍写出）。**默认用 1x 750px，稳定优先**；要 2x 需另做稳定性验证。
- 750px 宽接近手机阅读宽度，微信/QQ 里点开查看都合适；长图不要超过 20000px 高，避免部分客户端压缩/截断。

### 2.3 备选：Pillow 直接拼图（实测 750×1800）

无需浏览器，适合模板固定、纯文字/卡片的攻略：

```python
from PIL import Image, ImageDraw, ImageFont
W, H = 750, 1800
im = Image.new("RGB", (W, H), (250, 246, 238))
d = ImageDraw.Draw(im)
f1 = ImageFont.truetype("/System/Library/Fonts/Hiragino Sans GB.ttc", 42)
f2 = ImageFont.truetype("/System/Library/Fonts/Hiragino Sans GB.ttc", 20)
d.text((40, 40), "攻略标题", font=f1, fill=(36, 59, 42))
# 循环画卡片、段落……
im.save("攻略长图.png")
```

实测 Pillow 12.3.0 + Hiragino 中文渲染正常。缺点：排版要手写坐标，圆角/阴影/富文本不如 HTML 方便；适合作为 Edge 不可用时的兜底。

### 2.4 不推荐：screencapture 截网页/窗口

`screencapture` 能用（全屏和单窗口都成功），但它截的是屏幕像素：需要把页面滚到合适位置、拼接、处理 Retina 缩放，而且会受窗口遮挡/滚动条影响。只适合“截当前窗口”而不是“生成稳定长图”。

## 3. 四条路线评估与推荐

| 路线 | 做法 | 可行性（本机实测） | 风险 | 成本 | 结论 |
|---|---|---|---|---|---|
| **A. 长图 + 文案 → 剪贴板 → 用户自己粘贴** | 生成 750px 长图；文案 `pbcopy`；图片用 JXA 写 TIFF 到剪贴板；`open -a WeChat`；用户选人、Cmd+V、发送 | **高**：长图、中文、pbcopy、JXA 图片剪贴板、唤起 App 全部实测通过；仅“登录后微信粘贴”未验证（当前未登录） | 低：不自动点发送，不会误发；不依赖非官方协议 | 低：一个 HTML 模板 + 两条命令 | **默认推荐** |
| **B. 半自动：复制 + 唤起 + 可选打开搜索** | 在 A 基础上，脚本顺带用 AXPress 触发微信菜单“编辑→搜索”或“文件→发起会话”，或只把 App 置前；仍由用户选人、粘贴、发送 | **中**：剪贴板和唤起已验证；微信菜单项 AX 可读，但登录后的搜索框/输入框聚焦未验证 | 低-中：只要不自动按发送，最坏是焦点不对 | 低-中 | 可作为 A 的一键化包装，不做自动发送 |
| **C. 全自动 AX：搜联系人 → 粘贴 → 发送** | 用 AX/OCR/像素点击驱动微信或 QQ | **低/当前不可行**：微信 AXWindows=0（Qt 自绘），QQ 仅 25 个骨架元素、无输入框；cua 均 `ax_window_unresolved`；且两 App 未登录 | **高**：误发、发错人、账号风控、权限/焦点问题；无可用的稳定会话 ID | 高（要为每个版本适配） | **不建议** |
| **D. 机器人通道（OneBot QQ / 微信 bridge）** | 装 `dsh-onebot-qq`/`dsh-channel-qq` + NapCat/SnowLuma；或 `@lanbaolu/dsh-wechat-bridge` + 扫码 | **中**：插件本身成熟，但需要协议端、账号、常驻进程；本机未装、未测 | 中-高：非官方协议，账号风控/掉线；微信 bridge README 自述账号风险 | 高（部署+维护+账号） | 仅在需要长期自动通知时考虑 |

### 推荐落地顺序

1. **先做 A**：产出 `攻略长图.png` + `文案.txt`，加一个“复制并打开微信”的按钮/命令。
2. 用户登录微信/QQ 后，选“文件传输助手”或好友，Cmd+V，自己点发送。
3. 如果 A 用起来顺手，再把“复制 + 唤起 + 打开搜索”包成 B；仍然不自动发送。
4. C 先不做；等微信/QQ 版本更新后再评估。
5. D 只在“需要每天自动把攻略推到手机/群里”时立项，且优先用 QQ 官方机器人或企业微信，而不是个人号非官方协议。

## 4. 可直接用的最小脚本（A 路线）

```bash
#!/bin/bash
# 依赖：Microsoft Edge、osascript、pbcopy；微信需已登录
set -e
DIR="$(cd "$(dirname "$0")" && pwd)"
IMG="$DIR/攻略长图.png"
TXT="$DIR/文案.txt"

# 1) HTML -> 长图（高度按模板固定值改）
EDGE="/Applications/Microsoft Edge.app/Contents/MacOS/Microsoft Edge"
"$EDGE" --headless=new --no-sandbox --disable-gpu --disable-dev-shm-usage \
  --hide-scrollbars --user-data-dir=/tmp/dsh-edge-profile \
  --window-size=750,2200 --virtual-time-budget=3000 \
  --screenshot="$IMG" "file://$DIR/攻略长图.html"

# 2) 文案进剪贴板（UTF-8）
pbcopy < "$TXT"

# 3) 图片进剪贴板（JXA 写 TIFF；本机实测 types=public.tiff）
osascript -l JavaScript -e "
ObjC.import('AppKit');
var pb = $.NSPasteboard.generalPasteboard;
pb.clearContents;
var img = $.NSImage.alloc.initWithContentsOfFile('$IMG');
pb.setDataForType(img.TIFFRepresentation, $.NSPasteboardTypeTIFF);
"

# 4) 唤起微信（QQ 改成 open -a QQ）
open -a WeChat
```

使用顺序：先粘贴图片（Cmd+V）→ 再运行一次文案复制 → 粘贴文字 → 发送。因为剪贴板同一时刻只能放一种内容；如果希望“一次粘贴全都有”，把文案直接排进长图底部，或生成“图片 + 文案”两张图。

补充：DSH 内部有现成的 `clipboard_write({image_path})`，实测写入 `public.png/public.tiff` 成功；如果由 Agent 执行，可以直接用它，不必走 JXA。但给用户双击运行的脚本，JXA 更通用。

## 5. 证据与限制

### 已实测通过
- 微信/QQ 版本、bundle、share extension、URL scheme、登录状态
- `osascript get version`；窗口查询挂起；JXA windows=0
- `AXIsProcessTrusted()=1`；微信 AXSheet/菜单可读、AXWindows=0；QQ 25 元素、无输入框；cua `ax_window_unresolved`
- NSSharingServicePicker 只提议 8 个系统服务，无微信/QQ
- Edge headless 750×2200 中文长图；Pillow 750×1800 中文图
- `pbcopy` UTF-8；JXA TIFF 图片剪贴板；cua clipboard 图片写入
- `screencapture` 全屏/窗口截图；`qlmanage` HTML 失败；wkhtmltoimage/Chrome 缺失

### 未验证 / 限制
- **微信、QQ 当前均未登录**：登录后的“粘贴图片是否被接受”“文件传输助手是否可搜索”“QQ 登录后 AX 是否变化”均未做端到端验证。不要把它们写成已验证。
- 系统分享扩展为何不出现未确认；未改系统设置，未尝试启用。
- 没有向任何真实联系人发送消息（有意避免）。
- Edge 2x 渲染进程 segfault；1x 稳定。
- `dsh-onebot-qq` 的 npm 元数据抓取被截断，机制结论来自其 README 与 package.json；未实际安装/联调。
- 微信探测时被 osascript 启动，当前停在登录页；QQ 原本就在登录页。两者都没有被关闭/修改配置。

### 复现命令索引

```text
# OSAScript

# AX

/tmp/dsh-share-probe/axdump ax 2123
/tmp/dsh-share-probe/tools2 qqscan 64177
# long image

```
