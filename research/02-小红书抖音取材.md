|---|---|---|---|

## 2. 技术现实：为什么抓不到

### 2.1 小红书：双层门禁
1. **Token 门禁**：笔记页必须带真实 xsec_token（或 xhslink.com 短链）。裸链一律被判定"页面不见了"——注意返回的是 HTTP **200** + 一页空壳，不是 403/404，所以**不能用状态码判断成败**，必须看 noteDetailMap 是否为空。
2. **签名门禁**：即使页面壳加载了，正文也不在 HTML 里——__INITIAL_STATE__.note.noteDetailMap 恒为 {}，正文由前端 XHR 到 edith.xiaohongshu.com/api/sns/web/v1/feed 拉取，必须带 x-s / x-t 签名头（签名由页面内 JS 现算，依赖 window 上下文）。

**证据链**：X3/X4/X5–X7（SSR 中 noteDetailMap 为空）→ X9/X10（裸 GET 内部 API 404）→ 工具生态全部要求"cookie 或 登录态浏览器"（§3）→ 外部资料明确 x-s/x-t 需 JS 逆向。

### 2.2 抖音：三种页面，三种命运

| 页面类型 | 渲染方式 | 匿名可达 | 备注 |
|---|---|---|---|
| /search/*、/video/*、/note/*、/jingxuan、/discover | 客户端 SPA | ❌ 72,914 B 空壳 + _$jsvmprt | 所有路由共用一个壳，字节数一致 |
| /aweme/v1/web/... 数据接口 | JSON | ❌ 需 a_bogus 签名 + 凭证 | 失败形态是**静默空数组**，最难排查 |
| **/shipin/<video_id>** | **服务端渲染（SEO 落地页）** | ✅ | 正文明文 + <meta keywords/description> + 发布时间 + AI文稿 |

/shipin/ 页的 <meta name="keywords"> 存的是**该页对应的搜索词**（例：成都四个高铁站哪个离春熙路最近、成都3天2晚自由行攻略地图），说明这批页面是"关键词 → 视频簇"的 SEO 落地页，天然适合做**主题扩展**。

### 2.3 合规边界（robots.txt 原文要点）

**小红书**（https://www.xiaohongshu.com/robots.txt）：

    User-agent: Googlebot
    Disallow: /

    User-agent: Baiduspider / bingbot / 360Spider / Sogou* / YisouSpider
    Disallow: /
    Allow: /$
    Allow: /explore
    Allow: /sitemap.xml
    Allow: /sitemap-notes-

    User-agent: *
    Disallow: /

→ **除搜索引擎外全站禁止**；连搜索引擎也只放行 /、/explore（列表壳）和 sitemap，**笔记正文路径从未被放行**。

**抖音**（https://www.douyin.com/robots.txt）：

    # 第一组（Googlebot / Bingbot / ByteSpider / ToutiaoSpider / PerplexityBot / GPTBot / deepseekbot …）
    Disallow: /follow
    Disallow: *general_search*
    Disallow: *enter_from=*
    Disallow: *vid=*

    User-agent: Baiduspider
    Disallow: /video/
    Disallow: /note/
    Disallow: /shipin/
    Disallow: /search/

→ **/shipin/ 对通用爬虫是允许的**，只对 Baiduspider 单独禁止；且抖音把 deepseekbot、GPTBot、OAI-SearchBot 明确列进了白名单组。**这是本次唯一"明文允许"的通道**（仍需遵守频控与使用目的约束，robots 不是授权书）。

## 4. 三条路线评估

### A. 搜索引擎摘要 + 正文抓取（web_search / web_fetch，零依赖）

| 维度 | 评价 |
|---|---|
| 能拿到什么 | 小红书：**只有标题 + URL**（正文 0 字，裸链失效）。抖音：**标题 + 文案 + 发布时间 + 作者/粉丝数 + 互动数 + AI 文稿转写（ASR）**，单页 2.3k–8.5k 字 |
| 稳定性 | 抖音 /shipin/：**6/6 成功**，匿名、无 cookie、无签名，HTML 结构稳定（meta keywords/description + 文本块）。风险是这类 SEO 页可能被下线/改版。Bing/搜狗/360 的 site: 全部不可靠，发现层只能用 DSH 内置 web_search |
| 合规风险 | **抖音低**（robots.txt 明文允许 /shipin/）；**小红书中高**（robots Disallow: /，且技术上取不到） |
| 实现成本 | **最低**：一次 web_fetch + 正则/切块，无外部依赖、无登录、无浏览器。半天可落地 |
| 硬伤 | ① 只能"按 id 抓"，**不能按关键词搜**——发现新页仍依赖 web_search（每城 5–10 条 seed）；② AI 文稿是**语音识别**，有错字（实测："红海子"→"红孩子"、"中谷村"→"钟鼓春"），引用前必须人工核对；③ 页面是"相关视频聚合"，混入大量其他城市/线路内容，需要筛选 |

### B. 用户已登录浏览器自动化（cua driver / Playwright 连本地浏览器）

| 维度 | 评价 |
|---|---|
| 能拿到什么 | 理论上是**全部**：笔记正文、图片（可 OCR 菜单价目表）、评论（避坑点常在评论）、话题页。这是唯一能拿到小红书正文的路 |
| 稳定性 | 中。**本机实测已发现 5 个卡点**（见下） |
| 合规风险 | 中：用户自己的账号、自己的登录态、人类节奏操作，风险主要在"自动化行为"违反用户协议；**但绝不外传 cookie、不批量、不高频**，实际风险可控 |
| 实现成本 | 中高。需要用户先登录一次，再决定是"人工复制"还是"半自动读取" |

**本机环境实测（硬约束，必须写进方案）**：
1. cua_driver.list_apps() 正常，**Safari(pid 1619) 与 Edge(pid 1780) 都在运行**。
2. cua_driver.get_browser_state({pid:1780, window_id:363}) → **被拒**：browser_consent_required / consumer_profile_endpoint_requires_grant，要求先走 browser_prepare（existing_profile 策略 + 窗口授权锚点）。**即：cua 不能"默默地"驱动用户已有的 Edge profile。**
3. cua_driver.get_window_state(1780, 363) → **AX 树为空**，degraded_reason: ax_window_unresolved：该 Edge 窗口在**另一个 Space**（space_ids:[33]，当前 Space=101）。→ **要读浏览器内容，窗口必须先处于当前 Space/可见**。
4. 无 CDP 端点：curl 127.0.0.1:9222 → 无监听；~/Library/Caches/ms-playwright **不存在**（Playwright 需另行下载 Chromium，约 150 MB）。
5. Edge 的 Cookie 库（只统计域名，未解密）：.douyin.com 38 条、www.douyin.com 11 条、**xiaohongshu 相关 0 条** → **用户目前并没有在浏览器里登录过小红书**（只有抖音的匿名访问痕迹）。→ 走 B 之前，用户需要先手动登录一次。

> 结论：B 路线**可行但需要一次人工准备**（切 Space / 登录 / 授权）。最省事且风险最低的形态是 **"用户开页面 → 人工复制正文给我"**；如果要半自动，优先"截图 + 视觉读图"而不是 CDP 注入。

### C. 第三方 MCP / 爬虫库（要 cookie）

| 维度 | 评价 |
|---|---|
| 能拿到什么 | 结构化字段最全：笔记正文、作者、点赞/收藏、评论、话题（MediaCrawler / xhs-mcp 都是这套） |
| 稳定性 | 中低：依赖逆向签名，平台一改就崩（ReaJason/xhs 停更 16 个月即是例证）；xhs-auto-mcp 仓库已消失 |
| 合规风险 | **最高**：① cookie 等于账号凭证，落在第三方代码/日志里；② 平台用户协议明确禁止自动化采集；③ 小红书本就高频风控（异地登录、异常请求），**主力号有被限流/封号的实际风险**；④ MediaCrawler 自述"禁止商用、仅学习"，转载其抓到内容时版权归属也不清 |
| 实现成本 | 中（装 Python/uv 或 Go 二进制 + 浏览器 + 扫码），但**维护成本是持续的** |

## 5. 推荐（明确排序）

1. **抖音：走 A。** 用 web_search 拿 /shipin/<id> seed → web_fetch 抓页 → 本地解析出「标题 / 文案 / 发布时间 / 作者 / AI 文稿」。**零依赖、匿名、robots 允许、6/6 实测成功。**
2. **小红书：优先"人工粘贴"，其次 B 的截图读图，不要 C。** 用户自己在浏览器登录 → 复制正文/截图给我 → 我做结构化。若一定要半自动，用 cua driver 绑已登录窗口读截图/文本，**低频（每次 ≤5 篇）、只读、不点赞不评论不关注**。
3. **C 路线：仅在"用户明确接受封号风险 + 小号"时考虑，且不进交付主链。**
4. **票价/营业时间/预约规则一律不采信 xhs/douyin**，用高德/官方渠道二次校验（见 task-3）。

## 7. 落地脚本思路（A 路线，零依赖）

    1) 发现：web_search 查「<城市> 三日游 攻略 site:douyin.com」「<城市> 旅游攻略 抖音」→ 收 /shipin/<id>
    2) 抓取：web_fetch https://www.douyin.com/shipin/<id>
    3) 解析（node，无第三方包）：
       - <meta data-rh="true" name="keywords" content="...">    → 页面主题词
       - <meta data-rh="true" name="description" content="..."> → 主视频文案
       - 去 <script>/<style>/<tag> 后切块，正则取：
           发布时间：(\d{4}-\d{2}-\d{2} \d{2}:\d{2})
           作者：紧跟互动数之后的短行
           "AI文稿" 之后的段落 → 转写正文（按空行/数字边界切分）
    4) 归并：每城 5–10 页 → 文本块去重（按前 40 字）→ 输出 JSONL
    5) 校验：与人读一遍；票价/时间打「待官方校验」标记

**频控建议**：单批次 ≤10 页、页间 ≥3s、不要并发；只在生成某一城攻略时抓，不建库、不长期缓存全文（存摘要 + 出处链接即可）。

**小红书（B 路线）最小实现**：用户复制笔记正文 → 粘贴给我（零风险）。若做半自动：cua_driver 先把目标窗口切到当前 Space（否则 ax_window_unresolved）→ 截图 → 视觉读图，**不注入 JS、不读 cookie、不自动滚动超过必要次数**。

## 8. 风险与合规红线

1. **不做**：批量爬取、跨账号、代理池、把抓到的全文再分发/再发布、绕过登录墙。
2. **不碰**：用户 cookie、账号密码、扫码登录凭证的存储与传输。
3. **小红书**：robots 全站禁止 → 任何自动化抓取都属"平台不欢迎"行为；只做"用户自己登录、自己的人眼/低频操作"。
4. **抖音**：/shipin/ robots 允许，但仍遵守：只抓当前需要的几页、保留出处链接、**引用而非复制全文**、AI 文稿（ASR）必须标注"语音识别，可能有误"。
5. **版权**：攻略是他人作品，交付物里应写"素材来源 + 链接"，行程结构与决策由我们自己做，**不整段搬运**。
